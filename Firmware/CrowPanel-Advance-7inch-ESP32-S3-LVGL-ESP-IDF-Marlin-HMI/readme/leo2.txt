Quick Answer
To start the nozzle PID autotune in Pronterface, use the command M303 E0 S<temp> C8. 

M303: Initiates the PID calibration process. 
E0: Selects the first extruder (nozzle). 
S: Sets the target temperature (e.g., S210 for PLA).
C8: Specifies the number of heating/cooling cycles (e.g., 8 or 10). 
Example: M303 E0 S210 C8

After the process completes, Pronterface will display the new P, I, and D values.  Save these permanently to the firmware using M500.

Researched EEZ Studio button setup for ESP-IDF
In EEZ Studio with ESP-IDF, physical buttons (GPIO) aren't handled directly in the GUI editor — you wire them up in your C code and bridge them to the LVGL objects EEZ Studio generates. Here's the workflow:

1. Design the GUI in EEZ Studio
Add Button widgets to your page, give each a unique Name (e.g. btn_start, btn_stop).
In each button's Events section, attach a User Action (e.g. action_start, action_stop).
Build the project — EEZ Studio generates ui.h, ui.c, and actions.h in your src/ui/ folder. 
2. Implement the actions in C
In a C file in your project (e.g. actions.c), implement the user actions declared in actions.h:

#include "ui.h"
#include "actions.h"

void action_start(lv_event_t *e) {
    // your logic here
}

void action_stop(lv_event_t *e) {
    // your logic here
}

3. Wire up the physical GPIO buttons
In your main.c (or a dedicated file), configure the GPIO and use an ISR to trigger the same LVGL events:

#include "driver/gpio.h"
#include "ui.h"
#include "lvgl.h"

#define BTN_START_GPIO  GPIO_NUM_32
#define BTN_STOP_GPIO   GPIO_NUM_33

void IRAM_ATTR btn_isr(void *arg) {
    int btn = (int)arg;
    if (btn == BTN_START_GPIO) {
        lv_event_send(ui_get_obj("btn_start"), LV_EVENT_CLICKED, NULL);
    } else {
        lv_event_send(ui_get_obj("btn_stop"), LV_EVENT_CLICKED, NULL);
    }
}

void app_main(void) {
    // Init LVGL / EEZ UI
    ui_init();

    // Configure buttons as inputs with pull-up
    for (int pin = BTN_START_GPIO; pin <= BTN_STOP_GPIO; pin++) {
        gpio_set_direction(pin, GPIO_MODE_INPUT);
        gpio_set_pull_mode(pin, GPIO_PULLUP_ONLY);
        gpio_install_isr_service(0);
        gpio_isr_handler_add(pin, btn_isr, (void*)pin);
        gpio_set_intr_type(pin, GPIO_INTR_NEGEDGE);  // active-low: pressed = LOW
    }

    // Main loop (LVGL tick / flush handled by your display driver)
    while (1) {
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

Note: ui_get_obj("name") is the EEZ Studio helper to look up a widget by the name you set in the editor. If your project doesn't have that helper, you can instead store the lv_obj_t* pointers at init time and use them directly in the ISR. 

Key points
Debounce: Hardware pull-ups + a short software delay or edge-triggered interrupt handles most bouncing.
Active level: Most dev-kit buttons are wired to GND → use GPIO_INTR_NEGEDGE (falling edge). If wired to 3.3 V, use GPIO_INTR_POSEDGE.
lv_event_send must be called from the LVGL task context.  If your ISR runs in a different context, queue the event or use lv_async_call / a FreeRTOS queue to forward it safely.
The LVGL forum thread on this topic has a good walkthrough of the same pattern: forum.lvgl.io.

Analyzed CrowPanel GT911 bootloop crash
The crash is a firmware bug: the GT911 touch controller fails to initialize (I2C communication failure), but the code still registers the touchpad_read callback with LVGL. When LVGL's input timer fires, it calls touchpad_read at esp32_s3.c:386 which dereferences an uninitialized touch handle → jumps to 0x000493e0 (garbage) → InstrFetchProhibited → reboot loop.

The sequence in your log
E (1052) panel_io_i2c_rx_buffer: i2c transaction failed
E (1059) GT911: GT911 read error!
E (1070) GT911: Error (0x103)! Touch controller GT911 initialization failed!
...
Guru Meditation Error: Core 1 panic'ed (InstrFetchProhibited)
PC: 0x000493e0   ← invalid address (not 0x4xxxxxxx)

Fix (in your EEZ Studio project source)
In main/display/esp32_s3.c, around line 386 (touchpad_read), add a guard:

static lv_indev_t *touch_indev = NULL;
static esp_lcd_touch_handle_t touch_handle = NULL;

// Where you create the touch driver:
esp_err_t err = esp_lcd_touch_new_i2c_gt911(&i2c_cfg, &touch_cfg, &touch_handle);
if (err != ESP_OK) {
    ESP_LOGE("GT911", "Touch init failed (0x%x), skipping input registration", err);
    touch_handle = NULL;
    // Do NOT register the input device below
} else {
    // Register input device with LVGL as normal
    lv_indev_set_read_cb(touchpad, touchpad_read);
}

And in touchpad_read itself:

void touchpad_read(lv_indev_t *indev, lv_indev_data_t *data) {
    if (touch_handle == NULL) {
        data->state = LV_INDEV_STATE_RELEASED;
        return;
    }
    // ... existing read logic
}

Why the GT911 is failing
Since your STC8H1K28 (the helper MCU on the Advance board) initialized fine, the I2C bus itself is working. The likely causes are:

Cause	Check
Touch FPC ribbon cable not seated	Power off, reseat the touch ribbon connector
GT911 not powered/reset by STC8H1K28	Verify the STC8H1K28 firmware is the correct version for your board revision
I2C address mismatch	The GT911 may be at 0x14 instead of 0x5D — try both in your I2C config

Quick test: If you can't reseat the ribbon right now, the firmware guard above will stop the bootloop and let the display work (just without touch).

Researching CrowPanel USB power issues
That confirms it — insufficient power through the longer cable. The CrowPanel Advance 7" draws 8–10 W at full brightness, and the GT911 needs a clean 3.3 V rail (ripple ≤ 50 mV per its datasheet). A longer cable adds resistance → voltage sag → the GT911's 3.3 V drops below its operating range → I2C times out → the uninitialized handle crash.

The STC8H1K28 survives because it's more tolerant of marginal supply; the GT911 is not.

Fixes (pick one)
Option	Why it works
Short, thick USB-C cable (≤ 1 m, 20 AWG)	Less resistance, less voltage drop
Plug both USB-C ports (UART0-IN + USB 2.0)	Elecrow's own docs recommend this — the second port adds a parallel 5 V path
5 V / 2 A wall adapter into the UART0-IN port	Bypasses the PC port's limited current entirely

The Elecrow wiki explicitly warns:

"If the program utilizes screen functions, power consumption will reach 8–10 watts. If powered solely by the computer's USB port, insufficient power may cause the screen to go black." 

So the firmware guard I suggested earlier is still worth adding as a safety net, but the real fix is power: go back to a short cable or a proper 5 V/2 A supply and the GT911 will initialize normally.

Analyzed Marlin M115 serial buffer timing
The problem is your 10ms lock timeout. The LVGL task holds the mutex during lv_timer_handler() (rendering), and when your serial task tries lvgl_port_lock(pdMS_TO_TICKS(10)), it times out and drops the line. That's why you see batches — the lines that land between render frames get through, the ones during a frame are lost.

Fix: use a queue
Don't touch LVGL from the serial task at all. Buffer lines in a FreeRTOS queue, then drain it from the LVGL task:

#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "freertos/queue.h"

#define LOG_QUEUE_LEN  64
#define LOG_LINE_MAX   128

static QueueHandle_t log_queue = NULL;
static char log_buf[LOG_QUEUE_LEN][LOG_LINE_MAX];

void log_queue_init(void) {
    log_queue = xQueueCreate(LOG_QUEUE_LEN, sizeof(char*));
}

// Called from your serial task — no LVGL lock needed
void append_print_log(const char *line) {
    if (log_queue == NULL) return;
    // Copy line into a static buffer pool (or use a ring of pre-allocated buffers)
    int idx = (xTaskGetTickCount() % LOG_QUEUE_LEN);
    strncpy(log_buf[idx], line, LOG_LINE_MAX - 1);
    log_buf[idx][LOG_LINE_MAX - 1] = '\0';
    xQueueSend(log_queue, &log_buf[idx], 0);  // non-blocking
}

Then in your LVGL task (the lvgl_port_task loop in esp32_s3.c), after lv_timer_handler():

// Inside lvgl_port_task, after lv_timer_handler() and before vTaskDelay:
if (log_queue != NULL && objects.print_status_log != NULL) {
    char *line;
    while (xQueueReceive(log_queue, &line, 0) == pdTRUE) {
        lv_textarea_add_text(objects.print_status_log, line);
        lv_textarea_add_text(objects.print_status_log, "\n");
    }
}

This works because you're already holding the LVGL lock inside that task — no timeout, no dropped lines. The serial task just pushes to the queue and moves on.

Why your current code drops in batches
Timeline	What happens
Serial task receives line	Calls append_print_log → tries lock (10ms)
LVGL task is mid-render	Holds lock for ~50–100ms → your 10ms expires → line dropped
LVGL task releases lock	Next serial line gets through → you see a burst

The queue eliminates the contention entirely.

#define LOG_LINE_MAX   512   // was 128

Identified race condition in shared buffer logging
The drain: lines are empty — the queue is working, but the text is gone by the time LVGL reads it. Classic shared-buffer race: you're sending pointers into log_buf[], and the serial task overwrites that slot before the LVGL task gets to read it.

Fix: put the data in the queue, not pointers to external buffers
#define LOG_QUEUE_LEN  64
#define LOG_LINE_MAX   512

typedef struct {
    char line[LOG_LINE_MAX];
} log_item_t;

static QueueHandle_t log_queue = NULL;

void log_queue_init(void) {
    log_queue = xQueueCreate(LOG_QUEUE_LEN, sizeof(log_item_t));
}

void append_print_log(const char *line) {
    if (log_queue == NULL) return;
    log_item_t item;
    snprintf(item.line, LOG_LINE_MAX, "%s", line);
    xQueueSend(log_queue, &item, 0);  // copies the whole struct into the queue
}

And the drain in esp32_s3.c:

log_item_t item;
while (xQueueReceive(log_queue, &item, 0) == pdTRUE) {
    lv_textarea_add_text(objects.print_status_log, item.line);
    lv_textarea_add_text(objects.print_status_log, "\n");
}

You can delete the log_buf[] array entirely — the queue now owns the data. xQueueSend copies the struct into the queue's internal storage, so there's no shared memory between the two tasks.

static void marlin_tx_task(void *arg) {

static void marlin_tx_task(void *arg) {
    char cmd[MAX_GCODE_LEN];
    while (1) {
        if (xQueueReceive(marlin_cmd_queue, cmd, portMAX_DELAY)) {
            size_t len = strlen(cmd);
            if (cmd[len - 1] != '\n') {
                cmd[len] = '\n';
                len++;
            }
            ESP_LOGI("TX", "sending: %s", cmd);  // ← visible on your COM21 console
            uart_write_bytes(MARLIN_UART_NUM, cmd, len);
            uart_wait_tx_done(MARLIN_UART_NUM, pdMS_TO_TICKS(100));
        }
    }
}

static void marlin_rx_task(void *arg) {
    uint8_t rx_buf[256];
    static char line_accumulator[512];
    static size_t line_pos = 0;

    while (1) {
        int len = uart_read_bytes(MARLIN_UART_NUM, rx_buf, sizeof(rx_buf) - 1, pdMS_TO_TICKS(20));
        if (len > 0) {
            last_marlin_reply_ms = xTaskGetTickCount() * portTICK_PERIOD_MS;
            marlin_connected = true;

            for (int i = 0; i < len; i++) {
                char c = (char)rx_buf[i];
                if (c == '\n') {
                    line_accumulator[line_pos] = '\0';
                    if (line_pos > 0) {
                        snprintf(last_marlin_line, sizeof(last_marlin_line), "%s", line_accumulator);
                        new_line_ready = true;
                        
                        // 1. Always parse lines to update temperature dials and background state
                        parse_marlin_line(last_marlin_line);

                        // 2. Filter out temperature reports (T:) and basic ok acknowledgements 
                        //    so the console textarea doesn't get flooded.
                        if (strstr(last_marlin_line, "T:") == NULL && 
                            strcmp(last_marlin_line, "ok") != 0 && 
                            strncmp(last_marlin_line, "ok ", 3) != 0) {
                            append_print_log(last_marlin_line);
						if (strstr(line_accumulator, "Cap:") != NULL) {
							ESP_LOGI("MARLIN_RAW", "Accumulated: %s", line_accumulator);
						}	
                        }
                    }
                    line_pos = 0;
                } else if (c != '\r' && line_pos < sizeof(line_accumulator) - 1) {
                    line_accumulator[line_pos++] = c;
                }
            }
        }

    }

#define MARLIN_UART_NUM     UART_NUM_1
#define MARLIN_TX_PIN       GPIO_NUM_20
#define MARLIN_RX_PIN       GPIO_NUM_19
#define SERIAL_BUF_SIZE     1024
#define MAX_GCODE_LEN       64

#define FILE_NAME_LEN       64

// ─── Types ───────────────────────────────────────────────────────────────────

typedef struct {
    char line[LOG_LINE_MAX];
} log_item_t;

// ─── Globals ─────────────────────────────────────────────────────────────────

extern "C" QueueHandle_t log_queue = NULL;
QueueHandle_t marlin_cmd_queue = NULL;

static stc8h1k28_handle_t stc8 = NULL;
static const char *TAG = "MAIN";

bool marlin_connected = false;
bool isPrinting = false;
uint32_t last_marlin_reply_ms = 0;

// M20 file list state
static char file_list[MAX_FILES][FILE_NAME_LEN];
static int file_count = 0;
static bool capturing_files = false;

// ─── Forward declarations ────────────────────────────────────────────────────

extern "C" void update_clock_labels_timer(lv_timer_t *timer);
void parse_marlin_line(const char *line);

// ─── Log queue ───────────────────────────────────────────────────────────────

void log_queue_init(void) {
    log_queue = xQueueCreate(LOG_QUEUE_LEN, sizeof(log_item_t));
}

void append_print_log(const char *line) {
    if (log_queue == NULL) return;
    log_item_t item;
    snprintf(item.line, LOG_LINE_MAX, "%s", line);
    xQueueSend(log_queue, &item, 0);
}

// ─── G-code send ─────────────────────────────────────────────────────────────

extern "C" void send_gcode(const char *command) {
    if (!command) return;
    if (marlin_cmd_queue != NULL) {
        xQueueSend(marlin_cmd_queue, command, 0);
    }
    if (log_queue != NULL) {
        log_item_t item;
        snprintf(item.line, LOG_LINE_MAX, "> %s", command);
        xQueueSend(log_queue, &item, 0);
    }
}

// ─── File browser ────────────────────────────────────────────────────────────

static void update_file_browser_ui(void) {
    // Push clear + add commands through the log queue (drained in LVGL task)
    if (log_queue == NULL) return;

    log_item_t item;
    snprintf(item.line, LOG_LINE_MAX, "LIST_CLEAR");
    xQueueSend(log_queue, &item, 0);

    for (int i = 0; i < file_count; i++) {
        snprintf(item.line, LOG_LINE_MAX, "LIST_ADD:%s", file_list[i]);
        xQueueSend(log_queue, &item, 0);
    }
}

// ─── Marlin line parser ──────────────────────────────────────────────────────

void parse_marlin_line(const char *line) {
    if (line == NULL || strlen(line) == 0) return;

    // Temperature updates
    float hcur = -1, bcur = -1, dcur = -1;
    const char *tPos = strstr(line, "T:");
    if (tPos) sscanf(tPos, "T:%f", &hcur);
    const char *bPos = strstr(line, "B:");
    if (bPos) sscanf(bPos, "B:%f", &bcur);
    const char *cPos = strstr(line, "C:");
    if (cPos) sscanf(cPos, "C:%f", &dcur);

    char buf[16];
    if (hcur >= 0 && objects.nozzle_temp_main_screen) {
        snprintf(buf, sizeof(buf), "%.0f°", hcur);
        lv_label_set_text(objects.nozzle_temp_main_screen, buf);
    }
    if (bcur >= 0 && objects.bed_temp_main_screen) {
        snprintf(buf, sizeof(buf), "%.0f°", bcur);
        lv_label_set_text(objects.bed_temp_main_screen, buf);
    }
    if (dcur >= 0 && objects.drivers_temp_main_screen) {
        snprintf(buf, sizeof(buf), "%.0f°", dcur);
        lv_label_set_text(objects.drivers_temp_main_screen, buf);
    }

    // M20 file list parsing
    if (strcmp(line, "Begin file list") == 0) {
        file_count = 0;
        capturing_files = true;
        return;
    }
    if (strcmp(line, "End file list") == 0) {
        capturing_files = false;
        update_file_browser_ui();
        return;
    }
    if (capturing_files && file_count < MAX_FILES) {
        // Format: "0:filename.gcode  12345" or "1:SubFolder"
        char *colon = strchr(line, ':');
        if (colon) {
            char *name = colon + 1;
            // Strip trailing size (digits after last space)
            char *last_space = strrchr(name, ' ');
            if (last_space) {
                char *size_str = last_space + 1;
                bool is_size = (size_str[0] != '\0');
                for (char *p = size_str; *p; p++) {
                    if (*p < '0' || *p > '9') { is_size = false; break; }
                }
                if (is_size) *last_space = '\0';
            }
            snprintf(file_list[file_count], FILE_NAME_LEN, "%s", name);
            file_count++;
        }
    }
}

// ─── Tasks ───────────────────────────────────────────────────────────────────

static void marlin_tx_task(void *arg) {
    char cmd[MAX_GCODE_LEN];
    while (1) {
        if (xQueueReceive(marlin_cmd_queue, cmd, portMAX_DELAY)) {
            size_t len = strlen(cmd);
            if (cmd[len - 1] != '\n') {
                cmd[len] = '\n';
                len++;
            }
            uart_write_bytes(MARLIN_UART_NUM, cmd, len);
            uart_wait_tx_done(MARLIN_UART_NUM, pdMS_TO_TICKS(100));
        }
    }
}

static void marlin_rx_task(void *arg) {
    uint8_t rx_buf[256];
    static char line_accumulator[512];
    static size_t line_pos = 0;

    while (1) {
        int len = uart_read_bytes(MARLIN_UART_NUM, rx_buf, sizeof(rx_buf) - 1, pdMS_TO_TICKS(20));
        if (len > 0) {
            last_marlin_reply_ms = xTaskGetTickCount() * portTICK_PERIOD_MS;
            marlin_connected = true;

            for (int i = 0; i < len; i++) {
                char c = (char)rx_buf[i];
                if (c == '\n') {
                    line_accumulator[line_pos] = '\0';
                    if (line_pos > 0) {
                        parse_marlin_line(line_accumulator);

                        // Console: skip T: reports, bare "ok", and M20 list lines
                        if (strstr(line_accumulator, "T:") == NULL &&
                            strcmp(line_accumulator, "ok") != 0 &&
                            strncmp(line_accumulator, "ok ", 3) != 0 &&
                            !capturing_files &&
                            strcmp(line_accumulator, "Begin file list") != 0 &&
                            strcmp(line_accumulator, "End file list") != 0) {
                            append_print_log(line_accumulator);
                        }
                    }
                    line_pos = 0;
                } else if (c != '\r' && line_pos < sizeof(line_accumulator) - 1) {
                    line_accumulator[line_pos++] = c;
                }
            }
        }
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

static void status_poller_task(void *arg) {
    while (1) {
        if (isPrinting) send_gcode("M27");
        vTaskDelay(pdMS_TO_TICKS(2000));
    }
}

static void watchdog_task(void *arg) {
    while (1) {
        if (marlin_connected &&
            (xTaskGetTickCount() * portTICK_PERIOD_MS - last_marlin_reply_ms > 8000)) {
            marlin_connected = false;
            // Re-link: flush and send M115
            uart_flush(MARLIN_UART_NUM);
            send_gcode("M115");
        }
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

extern "C" void app_main(void)
{
    init_display();
    ESP_LOGI(TAG, "Start LVGL");

    // RTC
    struct tm rtc_time = {};
    if (bm8563_get_time(rtc_handle, &rtc_time) == ESP_OK) {

                 rtc_time.tm_year + 1900, rtc_time.tm_mon + 1, rtc_time.tm_mday,
                 rtc_time.tm_hour, rtc_time.tm_min, rtc_time.tm_sec);
        time_t t = mktime(&rtc_time);
        struct timeval tv = { .tv_sec = t, .tv_usec = 0 };
        settimeofday(&tv, NULL);
    }

    // Boot beep
    stc8 = stc8h1k28_get_handle();
    stc8h1k28_buzzer_on(stc8);
    vTaskDelay(pdMS_TO_TICKS(200));
    stc8h1k28_buzzer_off(stc8);

    // UART
    uart_config_t uart_config = {};
    uart_config.baud_rate   = 115200;
    uart_config.data_bits   = UART_DATA_8_BITS;
    uart_config.parity      = UART_PARITY_DISABLE;
    uart_config.stop_bits   = UART_STOP_BITS_1;
    uart_config.flow_ctrl   = UART_HW_FLOWCTRL_DISABLE;
    uart_config.source_clk  = UART_SCLK_DEFAULT;

    uart_param_config(MARLIN_UART_NUM, &uart_config);
    uart_set_pin(MARLIN_UART_NUM, MARLIN_TX_PIN, MARLIN_RX_PIN, UART_PIN_NO_CHANGE, UART_PIN_NO_CHANGE);
    uart_driver_install(MARLIN_UART_NUM, SERIAL_BUF_SIZE * 2, 0, 0, NULL, 0);

    // Queues
    log_queue_init();
    marlin_cmd_queue = xQueueCreate(COMMAND_QUEUE_LEN, MAX_GCODE_LEN);

    // UI
    if (lvgl_port_lock(portMAX_DELAY)) {
        ui_init();
        if (objects.print_status_log) {
            lv_textarea_set_text(objects.print_status_log, "");
        }
        lvgl_port_unlock();
    }

    // Tasks
    xTaskCreate(marlin_rx_task,      "rx",   4096, NULL, 5, NULL);
    xTaskCreate(marlin_tx_task,      "tx",   3072, NULL, 3, NULL);
    xTaskCreate(status_poller_task,  "poll", 2048, NULL, 2, NULL);
    xTaskCreate(watchdog_task,       "wd",   2048, NULL, 1, NULL);

    lv_timer_create(update_clock_labels_timer, 1000, NULL);

    // Initial link
    send_gcode("M155 S2");
    vTaskDelay(pdMS_TO_TICKS(200));
    send_gcode("M115");
}

Diagnosed LVGL textarea WDT cause
The WDT is killing your LVGL task, which is why the file list never populates — the drain block never runs long enough.

Root cause: lv_textarea_add_text triggers a full layout recalculation over all existing text every time you add a line. After a few hundred lines, that layout pass takes >30 seconds → WDT fires.

Fix: cap the textarea
In your drain block in esp32_s3.c, after adding text, trim old lines:

if (objects.print_status_log) {
    lv_textarea_add_text(objects.print_status_log, item.line);
    lv_textarea_add_text(objects.print_status_log, "\n");

    // Cap at ~50 lines to keep layout fast
    const char *txt = lv_textarea_get_text(objects.print_status_log);
    int newline_count = 0;
    for (const char *p = txt; *p; p++) {
        if (*p == '\n') newline_count++;
        if (newline_count > 50) break;
    }
    if (newline_count > 50) {
        // Find where to cut (after the 50th newline)
        int cut = 0, count = 0;
        for (int i = 0; txt[i]; i++) {
            if (txt[i] == '\n' && count == 50) { cut = i + 1; break; }
            if (txt[i] == '\n') count++;
        }
        if (cut > 0) {
            char *remaining = (char *)txt + cut;
            lv_textarea_set_text(objects.print_status_log, remaining);
        }
    }
}

Simpler alternative — just clear and re-set with a ring buffer:

#define MAX_CONSOLE_LINES  40
static char console_buf[MAX_CONSOLE_LINES][128];
static int console_idx = 0;

// In drain:
snprintf(console_buf[console_idx], 128, "%s", item.line);
console_idx = (console_idx + 1) % MAX_CONSOLE_LINES;

// Rebuild the string (only 40 lines max)
char full[40 * 129] = {0};
int off = 0;
for (int i = 0; i < MAX_CONSOLE_LINES; i++) {
    int idx = (console_idx + i) % MAX_CONSOLE_LINES;
    if (console_buf[idx][0]) {
        off += snprintf(full + off, sizeof(full) - off, "%s\n", console_buf[idx]);
    }
}
lv_textarea_set_text(objects.print_status_log, full);

This keeps the textarea at a fixed 40 lines max → layout stays fast → WDT stops → your LIST_ADD items get processed → file list populates.

// Cap textarea at 4000 chars to prevent WDT
const char *txt = lv_textarea_get_text(objects.print_status_log);

Analyzed LVGL textarea performance bottleneck
The problem is you're calling lv_textarea_add_text per line — each call triggers a full layout pass over all existing text. By line 20-30, each call is taking hundreds of ms. The fix is to batch all lines into one string and do a single lv_textarea_set_text per LVGL tick:

if (log_queue != NULL) {
    char batch[1024] = {0};
    size_t batch_len = 0;
    log_item_t item;

    while (xQueueReceive(log_queue, &item, 0) == pdTRUE) {
        if (strncmp(item.line, "LIST_ADD:", 9) == 0) {
            if (objects.file_browser_list) {
                lv_list_add_text(objects.file_browser_list, item.line + 9);
            }
        } else if (strcmp(item.line, "LIST_CLEAR") == 0) {
            if (objects.file_browser_list) {
                lv_obj_clean(objects.file_browser_list);
            }
        } else {
            if (batch_len < sizeof(batch) - 128) {
                batch_len += snprintf(batch + batch_len, sizeof(batch) - batch_len, "%s\n", item.line);
            }
        }
    }

    // ONE set_text per tick, not N add_text calls
    if (batch_len > 0 && objects.print_status_log) {
        const char *existing = lv_textarea_get_text(objects.print_status_log);
        size_t existing_len = strlen(existing);

        if (existing_len + batch_len > 500) {
            // Too long: just show the new batch (drop old)
            lv_textarea_set_text(objects.print_status_log, batch);
        } else {
            char combined[600];
            snprintf(combined, sizeof(combined), "%s%s", existing, batch);
            lv_textarea_set_text(objects.print_status_log, combined);
        }
    }
}

Why this fixes everything:

Before	After
N × lv_textarea_add_text (each triggers full layout)	1 × lv_textarea_set_text (single layout pass)
Layout cost grows with each line added	Layout cost is constant (max 500 chars)
LVGL task starves CPU1 → WDT → M115 spam	LVGL task finishes in <10ms → no WDT
File list never gets processed	LIST_ADD items handled in same tick

Also add the non-editable flag after ui_init() in app_main:

lv_obj_remove_flag(objects.print_status_log, LV_OBJ_FLAG_EDITABLE);

That eliminates cursor rendering overhead on top of the batched update.

Analyzed M105 spam and boot race condition
The >M105 spam is from send_gcode echoing every watchdog ping to the console. Two fixes:

1. Watchdog: bypass send_gcode, push directly to queue (no console echo):

static void watchdog_task(void *arg) {
    while (1) {
        if (marlin_connected &&
            (xTaskGetTickCount() * portTICK_PERIOD_MS - last_marlin_reply_ms > 8000)) {
            marlin_connected = false;
            uart_flush(MARLIN_UART_NUM);
            xQueueSend(marlin_cmd_queue, "M105", 0);  // no ">" echo
        }
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

2. Boot: retry M155 so Marlin actually gets it (it's not ready at t=0):

Replace the single send_gcode("M155 S2") at the end of app_main with:

// Wait for Marlin to come up, then enable temp autoreport
for (int i = 0; i < 5; i++) {
    send_gcode("M155 S2");
    vTaskDelay(pdMS_TO_TICKS(1000));
}

Once M155 S2 is active, Marlin pushes temps every 2 seconds automatically → last_marlin_reply_ms stays fresh → watchdog never fires → no M105 spam. The only >M155 S2 lines you'll see are the 5 boot retries.

Fixed Marlin file list parsing
Found it. Your Marlin sends file names without the N: index prefix:

SAVE/50MM_O~1.GCO 1403778
FACERE~1.GCO 3981918
STANDS~1.GCO 7829494

But your parser looks for a colon:

char *colon = strchr(line, ':');
if (colon) {  // ← always NULL, no colon in these lines

So no files ever get stored. Fix the parsing block in parse_marlin_line:

if (capturing_files && file_count < MAX_FILES) {
    const char *name = line;

    // Skip "N:" prefix if present (some Marlin versions include it)
    char *colon = strchr(line, ':');
    if (colon && (colon - line) < 3) {  // colon within first 2 chars = index
        name = colon + 1;
    }

    // Strip trailing size (digits after last space)
    char *tmp = (char *)name;  // we need to modify the string
    char *last_space = strrchr(tmp, ' ');
    if (last_space) {
        char *size_str = last_space + 1;
        bool is_size = (size_str[0] != '\0');
        for (char *p = size_str; *p; p++) {
            if (*p < '0' || *p > '9') { is_size = false; break; }
        }
        if (is_size) *last_space = '\0';
    }

    snprintf(file_list[file_count], FILE_NAME_LEN, "%.63s", tmp);
    file_count++;
}

The key change: if there's no colon (or the colon isn't in the first 2 chars), the whole line is the filename. The strrchr size-stripping still works the same way.

Also — remove that ESP_LOGI("M20", ...) debug line from the top of parse_marlin_line now that you've confirmed the format. It's flooding your serial console with every single line.

Implemented selectable file list with M23/M24 commands
Switch from lv_list_add_text to lv_list_add_btn and attach a click handler. The filename is passed via lv_obj_set_user_data:

In esp32_s3.c — add the callback above lvgl_port_task:

static void file_select_cb(lv_event_t *e) {
    lv_obj_t *btn = lv_event_get_target(e);
    const char *filename = (const char *)lv_obj_get_user_data(btn);
    if (filename) {
        // Send M23 (select) then M24 (start)
        char cmd[80];
        snprintf(cmd, sizeof(cmd), "M23 %s", filename);
        send_gcode(cmd);
        vTaskDelay(pdMS_TO_TICKS(100));  // small delay between M23 and M24
        send_gcode("M24");
    }
}

In the drain block — replace lv_list_add_text with:

if (strncmp(item.line, "LIST_ADD:", 9) == 0) {
    if (objects.file_browser_list) {
        const char *fname = item.line + 9;
        lv_obj_t *btn = lv_list_add_btn(objects.file_browser_list, NULL, fname);
        lv_obj_set_user_data(btn, (void *)fname);
        lv_obj_add_event_cb(btn, file_select_cb, LV_EVENT_CLICKED, NULL);
    }
}

One caveat: fname points into the log_item_t struct which is a local in the drain loop. Once the loop iteration ends, that memory is gone. You need to point it at the persistent file_list[] array instead.

static void update_file_browser_ui(void) {

    for (int i = 0; i < file_count; i++) {
        snprintf(item.line, LOG_LINE_MAX, "LIST_ADD:%d", i);
        xQueueSend(log_queue, &item, 0);
    }
}
